# נוהל פרסום

החזרה הכי תכופה בפרויקט: מועמד 2 ביומן נצפה 21 פעמים ומועמד 9 נצפה 20.

## איך הפרסום עובד כאן

`push` ל-`main` ← GitHub Action ← בנייה ← `cp .htaccess out/.htaccess`
← דחיפת `out/` לענף `deploy` ← Hostinger מסנכרן. **40 עד 60 שניות.**

הענף `deploy` נדחף עם `force_orphan`, ולכן קובץ שנמחק **כן** נעלם משם.

## הסדר

```bash
npx tsc --noEmit
npm run build
node scripts/content-verify.mjs <slug>      # אם נגענו בעמוד
git add <קבצים> && git commit && git push origin main
```

**לא `git add .`**: בריפו יש קבצי תמונה לא מעקב שאינם חלק מהשינוי.

## אימות חי, והחלק שבו טועים

```python
subprocess.run(['curl', '-s', '-w', '\n%{http_code}', '--max-time', '25',
                'https://carkeynow.co.il/<נתיב עברי>/?v=' + str(int(time.time()))])
```

שלוש אמיתות שעלו ביוקר:

1. **נתיב עברי לא עובר בשורת הפקודה של Git Bash.** ה-shell מעוות את
   ה-UTF-8, השרת מחזיר את דף הבית עם 200, וזה נראה כמו דפלוי מוצלח.
   (2026-09-19, ואבחנה שגויה שתוקנה רק ב-2026-10-26.)
2. **תמיד `?v=<timestamp>`.** בלי זה המטמון מחזיר את הגרסה הישנה.
   ב-2026-10-23 קיבלתי 200 על קובץ שכבר לא היה בשרת.
3. **שלוש מדידות, לא אחת.** צמתים שונים של ה-CDN מחזירים תשובות
   שונות. מדידה בודדת נתנה תמונה הפוכה מהמציאות **פעמיים באותה שעה.**

## כשמחליפים נכס קיים תחת אותה כתובת

לוגו, אייקון או תמונה שמוחלפים **חייבים `?v=` קבוע בכתובת שבדף**, לא רק
באימות. ה-CDN שומר תמונות לשנה לפי הכתובת. באייקונים זה יושב
ב-`app/layout.tsx`.

**מחיקת קובץ מהשרת אינה מספיקה:** המטמון ימשיך להגיש אותו, וניקוי
מטמון הוא פעולה ידנית ב-hPanel.

## אם הבנייה נכשלת

- `next/font` ← **לבדוק רשת לפני שמחפשים באג**: `curl -I https://fonts.googleapis.com`
- `EPERM: rmdir` ← `attrib -R "out\*" /S /D`
