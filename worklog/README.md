# יומן עבודה - carkeynow.co.il

תיעוד מסודר של כל מה שנעשה באתר: מה התבקש, מה בוצע, מה השתנה, מה נבדק,
ומה מהפעולות חוזר על עצמו מספיק פעמים כדי שיהיה שווה להפוך אותו לסקריפט.

## מה נמצא כאן

| קובץ | מה זה |
|---|---|
| `YYYY-MM-DD.md` | יומן יומי מלא. נכתב בסוף כל יום עבודה. |
| `AUTOMATION.md` | מצבור מועמדים לאוטומציה, מדורג לפי תדירות ורווח. מתעדכן כל יום. |
| `archive/git-history.md` | שחזור אוטומטי מהיסטוריית git לכל מה שקדם ליומן. **לא לערוך ידנית.** |

## מבנה יומן יומי

כל יום נכתב לפי אותם חמישה חלקים, באותו סדר:

```markdown
# YYYY-MM-DD

סיכום של שורה או שתיים: מה היה הנושא המרכזי של היום ומה יצא לאוויר.

## 1. מה ביקשת
ציטוט או תמצית מדויקת של הבקשה, כולל שינויי כיוון באמצע.

## 2. אילו פעולות בוצעו
לפי סדר כרונולוגי. כל פעולה בשורה, עם המספרים שלה.

## 3. מה השתנה
טבלת קבצים: קובץ, סוג השינוי, ומה בפועל השתנה בו.

## 4. אילו בדיקות הורצו
כל בדיקה והתוצאה שלה. בדיקה שנכשלה ותוקנה - לכתוב את שתי השורות.

## 5. מועמדים לאוטומציה
מה חזר על עצמו היום. כל שורה עוברת גם ל-AUTOMATION.md עם מונה.

## סטטוס בסוף היום
מה עלה לאוויר, מה נשאר פתוח, ומה מחכה להחלטה שלך.
```

## כללים לכתיבת היומן

- **מספרים, לא תיאורים.** "86 עמודים קיבלו סליידר" ולא "הרבה עמודים".
- **בדיקות שנכשלו נשארות ביומן.** הן החומר הכי שימושי לאוטומציה.
- **החלטות ונימוקים.** למה *לא* עשינו משהו חשוב לא פחות ממה שכן.
- **מה שנשאר פתוח נכתב בסוף.** כדי שאפשר יהיה להתחיל את היום הבא מהיומן.
- **הפניות לקומיטים** בפורמט `hash` כדי לחזור לשינוי המדויק.

## איך לחפש ביומן

```bash
grep -rl "קודן" worklog/                # באילו ימים עבדנו על קודן
grep -rn "נכשל\|בעיה\|תקלה" worklog/    # כל התקלות שהיו
node scripts/worklog-git.mjs            # רענון הארכיון מ-git
```

## למה זה קיים

שלוש מטרות, לפי סדר חשיבות:

1. **לזהות עבודה חוזרת.** אותה סדרת פעולות שחוזרת שלוש פעמים היא סקריפט
   שלא נכתב. `AUTOMATION.md` הוא הרשימה הזאת.
2. **לחזור אחורה.** לדעת מתי עמוד עלה, למה נבחרה גישה מסוימת, ומה כבר נוסה
   ולא עבד, בלי לחפור ב-diffים.
3. **המשכיות בין ימים.** כל יום מתחיל מהסעיף "מה נשאר פתוח" של היום הקודם.
